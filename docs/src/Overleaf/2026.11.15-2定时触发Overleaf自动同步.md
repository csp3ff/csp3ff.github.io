# 自建 Overleaf 每天 06:00 自动同步到 Gitee

前一篇记录了如何将自建 Overleaf 的编译文件同步到 Gitee 私有仓库。这次在已有仓库绑定的基础上，加了批量入口和 systemd 定时器。宿主机每天北京时间 06:00 检查当前可见的 Overleaf 编译目录，同步其中已绑定仓库的项目。[自建 Overleaf 同步到 Gitee 私有仓库](https://chatgpt.com/library?file_id=libfile_3e24ef7892d081919adf5eb033521c6d&account_id=personal) · [原始参考 hionwi/overleaf-sh](https://github.com/hionwi/overleaf-sh)

## 1. 批量同步是怎么运行的

| 组件 | 作用 |
| --- | --- |
| `auto-overleaf-gitee-sync.sh` | `--list` 列出完整编译目录名，传入一个目录名时同步对应项目 |
| `auto-overleaf-gitee-sync-timer.sh` | 逐个检查 `--list` 的结果。有 `gitee.json` 仓库绑定的目录才同步，未初始化的跳过 |
| `overleaf-gitee-sync.service` | 以 `<你的用户名>` 用户身份运行一次批量同步，并加载 Gitee 令牌 |
| `overleaf-gitee-sync.timer` | 每天北京时间 06:00 启动上述服务，关机错过后在定时器恢复时补跑一次 |

绑定后的项目如果出现文件新增、修改或删除，单项目脚本会创建 Git 提交。文件无变化时会继续尝试推送现有提交，因此上次推送失败可以在本次重试。脚本校验 Gitee 的 `main` 与本地提交一致后才算同步成功。一个项目失败时，批量脚本仍会处理后面的项目。

## 2. 操作步骤

### 第一步　检查脚本和项目绑定

以下命令在 Overleaf 宿主机上以 `<你的用户名>` 用户执行。将命令行版 `overleaf-gitee-sync.sh` 放到下列目录，命名为 `auto-overleaf-gitee-sync.sh`。将批量脚本 `overleaf-gitee-sync-autotimer.sh` 放在同一目录，沿用本次实际部署的文件名 `auto-overleaf-gitee-sync-timer.sh`。如果已按该文件名部署，直接检查即可。[overleaf-gitee-sync.sh](https://chatgpt.com/library?file_id=libfile_0394dc65bc948191924b0622716cba6e&account_id=personal) · [overleaf-gitee-sync-autotimer.sh](https://chatgpt.com/library?file_id=libfile_650660605ab48191b8294d58b7f10ceb&account_id=personal)

```bash
cd /home/<你的用户名>/data/overleaf-toolkit/overleaf-git-sync

ls -l auto-overleaf-gitee-sync{,-timer}.sh
bash ./auto-overleaf-gitee-sync.sh --list
```

列表中的每一行是完整的编译目录名，形如 `<项目ID>-<用户ID>`。此前已手动同步的项目可以直接复用仓库绑定。新增项目时，先在 Overleaf 重新编译，再用列表中的完整目录名手动初始化一次。下面以要新建的仓库 `my-overleaf-project` 为例。

```bash
project_id='替换为 --list 输出的完整目录名'
bash ./auto-overleaf-gitee-sync.sh "$project_id" my-overleaf-project
```

首次同步会创建私有仓库并保存绑定。默认绑定文件位于 `~/.local/state/overleaf-gitee/sharelatex/<完整编译目录名>/gitee.json`。现有绑定以执行首次同步的用户和状态目录为准。

### 第二步　保存 Gitee 私人令牌

Gitee API 用令牌核验仓库身份和私有状态，Git 推送走 SSH。已绑定的项目也会进行 API 校验，因此服务每次启动都要能读取令牌。`/etc/overleaf-gitee-sync.env` 已配置且令牌有效时，可以直接跳到第三步。

执行以下命令，按提示粘贴带 `projects` 权限的 Gitee 私人令牌。终端会隐藏输入，保存后的文件权限为 `0600`，由 root 持有。令牌过期或撤销后可重跑这一步。

```bash
sudo -v
bash <<'BASH'
set -euo pipefail
read -r -s -p '请输入 Gitee 私人令牌：' token </dev/tty
printf '\n'
[[ $token =~ ^[A-Za-z0-9_.-]+$ ]] || {
    echo '令牌为空或格式无效' >&2
    exit 1
}
printf 'GITEE_TOKEN=%s\n' "$token" |
    sudo bash -c '
        set -e
        umask 077
        tmp=$(mktemp /etc/overleaf-gitee-sync.env.XXXXXX)
        trap "rm -f -- \"\$tmp\"" EXIT
        cat > "$tmp"
        mv -f -- "$tmp" /etc/overleaf-gitee-sync.env
    '
BASH
```

### 第三步　写入 systemd 服务和定时器

本次部署的容器叫 `sharelatex`。若沿用旧的单项目服务，下面两段命令会写入同名服务和定时器，将服务入口切换到批量脚本。

```bash
sudo tee /etc/systemd/system/overleaf-gitee-sync.service >/dev/null <<'EOF'
[Unit]
Description=Sync bound Overleaf projects to Gitee
Wants=network-online.target docker.service
After=network-online.target docker.service

[Service]
Type=oneshot
User=<你的用户名>
SupplementaryGroups=docker
WorkingDirectory=/home/<你的用户名>/data/overleaf-toolkit/overleaf-git-sync
Environment=HOME=/home/<你的用户名>
Environment=OVERLEAF_CONTAINER=sharelatex
Environment=OVERLEAF_GIT_STATE=/home/<你的用户名>/.local/state/overleaf-gitee
Environment="GIT_SSH_COMMAND=/usr/bin/ssh -o BatchMode=yes"
EnvironmentFile=/etc/overleaf-gitee-sync.env
ExecStart=/bin/bash /home/<你的用户名>/data/overleaf-toolkit/overleaf-git-sync/auto-overleaf-gitee-sync-timer.sh
TimeoutStartSec=30min
EOF

sudo tee /etc/systemd/system/overleaf-gitee-sync.timer >/dev/null <<'EOF'
[Unit]
Description=Run Overleaf Gitee sync daily at 06:00 Beijing time

[Timer]
OnCalendar=*-*-* 06:00:00 Asia/Shanghai
AccuracySec=1s
Persistent=true
Unit=overleaf-gitee-sync.service

[Install]
WantedBy=timers.target
EOF
```

`OnCalendar` 显式指定 `Asia/Shanghai`。`Persistent=true` 会在定时器恢复时补跑错过的日程。`EnvironmentFile` 由 systemd 在启动服务时读取。[systemd.timer 文档](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html) · [systemd.exec 文档](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)

### 第四步　试跑并启用定时器

```bash
sudo systemctl daemon-reload &&
sudo systemctl start overleaf-gitee-sync.service &&
sudo systemctl enable overleaf-gitee-sync.timer &&
sudo systemctl restart overleaf-gitee-sync.timer &&
systemctl list-timers --all overleaf-gitee-sync.timer
```

手动试跑成功后，命令才会继续启用定时器。检查 `NEXT` 是否对应下次北京时间 06:00。`NEXT` 的显示时区跟随宿主机，可用下面的命令单独验证北京时间的触发表达式。

```bash
TZ=Asia/Shanghai systemd-analyze calendar '*-*-* 06:00:00 Asia/Shanghai'
sudo journalctl -u overleaf-gitee-sync.service -n 50 --no-pager
```

本次手动试跑时，一个已绑定项目返回了 `Everything up-to-date`，另一个未绑定项目被跳过。按新版脚本的统计格式，这次结果为：

```text
[overleaf-gitee-sync-autotimer] 完成：成功 1（更新 0，已最新 1），跳过 1，失败 0
```

「已最新」表示 Git 输出了 `Everything up-to-date`，且随后的远端校验通过。「更新」对应其余同步成功的项目，包括这次推送成功的旧提交。单项目报错时会计入「失败」，批量运行结束后服务会以非零状态退出。若要验证新提交的推送，在 Overleaf 保存修改并重新编译，手动启动服务，再到 Gitee 的 `main` 查看提交。

日常需要立即同步时，直接复用该服务：

```bash
sudo systemctl start overleaf-gitee-sync.service
sudo journalctl -u overleaf-gitee-sync.service -n 50 --no-pager
```

## 3. 遇到的问题与解决方法

### 问题 1　用 `sh` 运行时报 `set: Illegal option -o pipefail`

### 解决方法 1

脚本使用 Bash 的 `pipefail`。直接运行时用 `bash ./auto-overleaf-gitee-sync-timer.sh`。systemd 的 `ExecStart` 已通过 `/bin/bash` 调用脚本。显式使用 `sh 脚本名` 会由 `sh` 解释脚本，跳过文件首行的 Bash shebang。

### 问题 2　直接运行批量脚本时提示缺少 `GITEE_TOKEN`

### 解决方法 2

`EnvironmentFile=` 只在 systemd 启动服务时生效。手动立即同步也用 `sudo systemctl start overleaf-gitee-sync.service`，服务会自动加载保存的令牌。若服务仍报令牌错误，按第二步重新保存令牌，然后启动服务查看日志。

### 问题 3　自动同步前是否需要运行 `--preview`？

### 解决方法 3

批量入口运行 `--list` 后，直接把完整目录名传给单项目脚本。`--preview` 供人工核对将纳入 Git 的文件列表，定时运行时可以省略。

### 问题 4　日志里的 `/tmp/tmp.*` 目录何时删除？

### 解决方法 4

单项目脚本将编译文件暂存在这个目录，再通过 `trap 'rm -rf -- "$snapshot"' EXIT` 清理。正常完成和常规报错退出都会执行清理。进程被 `kill -9` 强制终止或宿主机断电时，目录可能残留。排查时可用 `test ! -e /tmp/具体目录名` 检查。Git 提交和仓库绑定保存在 `~/.local/state/overleaf-gitee/` 下。

### 问题 5　网页明明改过，为什么 Gitee 仍是旧内容？

### 解决方法 5

自动同步读取容器里的编译快照，`--list` 也只列出当前可见的编译目录。先在 Overleaf 中重新编译，再通过服务立即同步。如果日志显示「尚未手动绑定」，还要检查完整编译目录名和服务所用的 `OVERLEAF_GIT_STATE`，并为确实未绑定的目录完成首次同步。

### 问题 6　手动同步能推送，定时服务却认证失败

### 解决方法 6

服务以 `<你的用户名>` 运行，并通过 `BatchMode=yes` 禁用 SSH 交互。检查该用户的 Gitee 密钥和 `known_hosts`。如果平时靠当前终端的 SSH agent 或手动输口令解锁密钥，服务需要配置可在其自身环境中使用的 SSH 凭据。Docker 权限也要检查，确保服务可以访问 `sharelatex` 容器。

```bash
sudo -u <你的用户名> -H ssh -o BatchMode=yes -T git@gitee.com
sudo -u <你的用户名> -H docker exec sharelatex test -d /var/lib/overleaf/data/compiles
```

Gitee 的 SSH 测试以是否出现认证成功提示为准。完整的服务运行结果以 `journalctl` 中的同步日志为准。
