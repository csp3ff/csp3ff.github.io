# 自建 Overleaf 同步到 Gitee 私有仓库

## 1. 改造同步脚本

参考项目是 [hionwi/overleaf-sh](https://github.com/hionwi/overleaf-sh)。这次基于手头的 GitHub 版脚本改成 Gitee 版，保留分段注释、彩色输出、项目编号菜单和清理选项。本文使用的文件是 overleaf-gitee-sync.sh （见页末）。

改动主要有三处：

1. **首次同步自动建仓。** 把 GitHub CLI 建仓改为调用 Gitee API 的 `POST /user/repos`，指定 `private: true` 和 `auto_init: false`。在菜单里选中编译目录后，输入一个未使用的仓库名，脚本就在令牌所属的个人账号下创建空的私有仓库。后续根据本地记录复用该仓库。[Gitee API 文档](https://gitee.com/api/v5/swagger)
2. **Git 和 SSH 放在宿主机上。** 脚本将容器编译目录复制到宿主机临时目录，在本地裸仓库 `repo.git` 中保存提交，再经 SSH 推送。临时目录在脚本退出时清理。
3. **检查变化及推送结果。** Git 检查新增、修改和删除。推送前通过 API 核对仓库 ID、路径和私有状态，使用普通推送。确认 Gitee 的 `main` 指向本次同步的提交后，才记录最后成功同步时间。

每个选中的编译目录对应一个 Gitee 仓库。Gitee 上的 `.tex`、`.bib` 和图片保留原目录结构。脚本按 Overleaf → Gitee 单向同步，以容器中的编译快照为来源。Overleaf 网页里的版本历史、评论和权限需要通过其他途径备份。

## 2. 操作步骤

### 第一步　准备宿主机和依赖

把脚本放到运行 Overleaf 的 Linux 主机。Debian 或 Ubuntu 可执行：

```bash
sudo apt update
sudo apt install -y git curl jq openssh-client util-linux
sudo docker ps --format '{{.Names}}'
```

默认容器名是 `sharelatex`。建议以配置了 Gitee SSH 密钥的普通用户运行脚本，脚本会按需单独对 Docker 命令使用 `sudo`。

### 第二步　配置 Gitee 令牌和 SSH

在 [Gitee 私人令牌页面](https://gitee.com/profile/personal_access_tokens) 创建令牌，勾选 `projects` 权限。令牌用于自动建仓和推送前查询仓库状态。

SSH 用于实际推送。已有可用的 Gitee SSH 密钥时，直接运行本节最后的验证命令。需要新建密钥时，在宿主机上执行：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/overleaf_gitee -C "overleaf-gitee"
cat ~/.ssh/overleaf_gitee.pub
```

将输出的公钥添加到 [Gitee SSH 公钥设置](https://gitee.com/profile/sshkeys)。编辑 `~/.ssh/config`，加入下面的配置。已有 `Host gitee.com` 条目时，在对应条目中合并设置。[Gitee SSH 帮助](https://help.gitee.com/repository/ssh/questions/)

```sshconfig
Host gitee.com
    User git
    IdentityFile ~/.ssh/overleaf_gitee
    IdentitiesOnly yes
```

```bash
chmod 600 ~/.ssh/config
ssh -T git@gitee.com
```

确认欢迎信息里的 Gitee 账号与你创建令牌的账号一致。

### 第三步　重新编译并确定目标目录

打开目标 Overleaf 项目，点一次「重新编译」，然后在宿主机上查看容器内的编译目录：

```bash
sudo docker exec sharelatex ls -lah /var/lib/overleaf/data/compiles/
```

目录名若形如 `<项目ID>-<用户ID>`，用第一段与浏览器地址栏 `/project/` 后面的 ID 对照。菜单会显示完整目录名。如果想进一步核对文件，可以执行：

```bash
compile_dir='替换成完整编译目录名'
sudo docker exec sharelatex ls -lah "/var/lib/overleaf/data/compiles/$compile_dir"
```

### 第四步　通过菜单首次同步

```bash
bash overleaf-gitee-menu.sh "首次同步 Overleaf 项目"
```

1. 输入目标编译目录的菜单序号，然后输入 `1` 选择同步。
2. 为首次同步的目录填写新仓库名，例如 `seu-phd-slides`。
3. 按提示粘贴 Gitee 私人令牌。终端输入不会回显。
4. 看到「同步成功」后，打开输出中的 Gitee 地址，检查仓库的私有状态、`main` 分支、源文件和图片。

### 第五步　再次同步

在 Overleaf 重新编译后，再次运行脚本。选择同一个编译目录，输入 `1`。脚本读取已有映射，继续同步到同一个仓库。省略提交说明时默认使用 `Update thesis`。

```bash
bash overleaf-gitee-menu.sh "更新项目内容"
```

## 3. 遇到的问题与解决方法

### 问题 1：编译目录在哪里，怎样找到目标项目？

编译目录在容器内，默认路径是 `/var/lib/overleaf/data/compiles/`。列表里看到的长字符串是编译目录名。只列出一个目录，说明此时该位置只有一个编译目录。网页上的项目总数应在项目列表中查看。

### 解决方法 1

先重新编译目标项目，通过第三步的命令查看目录并核对项目 ID。如果提示找不到容器，用 `sudo docker ps` 查容器名。如果容器名或编译路径与默认值不同，可以按实际情况设置：

```bash
export OVERLEAF_CONTAINER='实际容器名'
export OVERLEAF_COMPILE_ROOT='/容器内的实际编译目录'
```

如果还要找宿主机上的挂载路径，查看 Docker 挂载关系。输出左侧是宿主机路径，右侧是容器内路径。

```bash
sudo docker inspect sharelatex \
  --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
```

### 问题 2：每次都要选 Gitee 仓库吗？

仓库名在首次同步时填写一次。脚本建仓后，将 Gitee 仓库 ID 和 `账号名/仓库名` 保存在该编译目录对应的 `gitee.json` 中。

### 解决方法 2

后续只需在菜单选中同一个编译目录。用同一个 Linux 用户运行脚本，默认即可读到原映射。如果用 `sudo` 运行整个脚本，本地状态路径会跟随脚本进程的 `$HOME`，可能落到 `/root` 下。

### 问题 3：为什么本地 `repo.git` 里只有 `objects` 和 `refs`，Gitee 却能显示项目文件？

`repo.git` 是 Git 裸仓库，作用类似普通工作目录里的 `.git/`。项目文件内容和目录结构保存在 Git 对象中，`main` 指向一份提交。Gitee 网页把这份提交的文件树展示出来。容器里的编译目录是读取来源，脚本在宿主机初始化 `repo.git`。脚本用来暂存 `.tex` 和图片的宿主机临时目录会在退出时清理。

### 解决方法 3

在宿主机上定位项目的本地同步状态目录，再查看 `main` 的文件列表和历史：

```bash
compile_dir='替换成完整编译目录名'
state_root="${OVERLEAF_GIT_STATE:-$HOME/.local/state/overleaf-gitee}"
container="${OVERLEAF_CONTAINER:-sharelatex}"
state="$state_root/$container/$compile_dir"
repo="$state/repo.git"

ls -lah "$state"
git --git-dir="$repo" ls-tree -r --name-only main
git --git-dir="$repo" log --oneline -5 main
```

| 本地条目 | 用途 |
|---|---|
| `repo.git` | 保存文件快照、分支和提交历史 |
| `gitee.json` | 保存对应的 Gitee 仓库 ID 和路径 |
| `last-success` | 记录最后成功同步时间 |
| `sync.lock` | 防止同一项目的同步与清理并发执行 |

如果需要一份可以用 `ls` 或 VS Code 浏览的工作目录，克隆本地仓库：

```bash
git clone --branch main "$repo" "$HOME/overleaf-project-copy"
```

### 问题 4：后续同步会自动检测修改吗？

当前菜单版在运行时检查编译目录的变化。发现改动就提交。没有改动时仍会尝试推送并校验远端，便于重试上次未推送成功的提交。脚本本身没有定时器，也没有监听网页编辑。

### 解决方法 4

手动同步时，在 Overleaf 重新编译，再运行脚本。如果需要定时同步，先给脚本增加一个按**完整编译目录名**选择项目的非交互入口，再用 cron 或 systemd timer 调用。还需要为定时任务预先提供 `GITEE_TOKEN`，并确认运行用户的 Docker 权限和 SSH 认证可在无需输入的情况下工作。定时推送只读取已有编译快照，网页修改要进入该快照仍需触发 Overleaf 编译。[Overleaf 自建部署文档](https://docs.overleaf.com/on-premises/support/troubleshooting)

### 问题 5：首次仓库建好了，但 SSH 推送失败，怎么重试？

脚本在推送前保存仓库映射。只要映射已经写入，再次运行就会复用原来的 Gitee 仓库。

### 解决方法 5

先用 `ssh -T git@gitee.com` 检查宿主机上的 SSH 身份，再重新选择原编译目录并同步。菜单上的「最后成功同步」要等远端提交核验通过才会更新。菜单中的 `2` 是清理操作，会删除编译缓存、本地 Git 历史和仓库映射，同时保留 Gitee 远端仓库。


### 代码

```shell
#!/bin/bash
set -euo pipefail
umask 077

# ===============================
# 🎨 颜色与格式配置
# ===============================
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
BLUE='\033[0;34m'
CYAN='\033[0;36m'
NC='\033[0m'

log() { printf '%b%s%b\n' "$1" "$2" "$NC"; }
die() { log "$RED" "❌ $*" >&2; exit 1; }

if [[ ${1:-} == -h || ${1:-} == --help ]]; then
    printf '%s\n' '用法：bash overleaf-gitee-menu.sh [提交说明]' \
        '可选环境变量：OVERLEAF_CONTAINER、OVERLEAF_COMPILE_ROOT、OVERLEAF_GIT_STATE、GITEE_TOKEN'
    exit 0
fi
(( $# <= 1 )) || die "只接受一个可选参数：提交说明"

# ===============================
# 🛡️ 权限与依赖检查
# ===============================
# Git 和 SSH 在宿主机运行；仅 Docker 命令按需使用 sudo。
for cmd in docker git curl jq flock; do
    command -v "$cmd" >/dev/null || die "宿主机缺少 $cmd。Debian/Ubuntu 可安装 git curl jq openssh-client util-linux"
done

# ===============================
# ⚙️ 配置参数
# ===============================
message=${1:-Update thesis}
container=${OVERLEAF_CONTAINER:-sharelatex}
compile_root=${OVERLEAF_COMPILE_ROOT:-/var/lib/overleaf/data/compiles}
state_root=${OVERLEAF_GIT_STATE:-"$HOME/.local/state/overleaf-gitee"}
[[ $container =~ ^[a-zA-Z0-9][a-zA-Z0-9_.-]*$ ]] || die "无效的容器名"
[[ $compile_root == /* ]] || die "编译目录必须是容器内的绝对路径"
compile_root=${compile_root%/}

docker_container() {
    if (( EUID == 0 )); then
        docker "$@"
    elif [[ -n ${docker_with_sudo:-} ]]; then
        sudo docker "$@"
    else
        docker "$@"
    fi
}
if (( EUID != 0 )) && ! docker inspect --type container "$container" >/dev/null 2>&1; then
    docker_with_sudo=1
fi

# ===============================
# 📂 1. 检查 Overleaf 编译目录
# ===============================
log "$BLUE" "🔍 正在扫描 Overleaf 容器内的编译目录..."
project_ids=$(docker_container exec "$container" sh -c '
    test -d "$1" || exit 1
    for path in "$1"/*; do
        if [ -d "$path" ] && [ ! -L "$path" ]; then printf "%s\n" "${path##*/}"; fi
    done
' sh "$compile_root") || die "无法读取编译目录 $compile_root，请检查容器名和路径"
[[ -n $project_ids ]] || die "编译目录为空，请在 Overleaf 重新编译目标项目"
mapfile -t option_ids <<<"$project_ids"

# ===============================
# 📊 2. 构建项目菜单
# ===============================
printf '\n'
log "$CYAN" '📋 检测到以下 Overleaf 编译目录：'
printf '序号\t编译目录名\t项目标识\t最后成功同步\tGitee 仓库\n'
for i in "${!option_ids[@]}"; do
    id=${option_ids[$i]}
    [[ $id =~ ^[a-zA-Z0-9][a-zA-Z0-9_.-]*$ ]] || die "发现不支持的编译目录名：$id"
    option_state="$state_root/$container/$id"
    full_name='---'
    label='未配置'
    label_color=$RED
    last_sync='从未同步'
    if [[ -f $option_state/gitee.json ]]; then
        full_name=$(jq -er '.full_name | strings' "$option_state/gitee.json") ||
            die "无法读取项目 $id 的仓库映射"
        label=${full_name#*/}
        label_color=$GREEN
    fi
    if [[ -f $option_state/last-success ]]; then
        last_sync=$(cat -- "$option_state/last-success")
    fi
    printf '%d\t%s\t%b%s%b\t%b%s%b\t%s\n' \
        "$((i + 1))" "$id" "$label_color" "$label" "$NC" "$YELLOW" "$last_sync" "$NC" "$full_name"
done

# ===============================
# ⌨️ 3. 用户选择项目
# ===============================
printf '\n'
log "$YELLOW" "请输入项目的序号 (1-${#option_ids[@]})："
read -r selection || die "未读取到项目序号"
option_count=${#option_ids[@]}
[[ $selection =~ ^[1-9][0-9]*$ && ${#selection} -le ${#option_count} ]] ||
    die "无效的选择，脚本退出"
(( selection <= ${#option_ids[@]} )) || die "无效的选择，脚本退出"
project=${option_ids[selection - 1]}
source_dir="$compile_root/$project"
state="$state_root/$container/$project"
binding="$state/gitee.json"
repo_git="$state/repo.git"
current_label='未配置'
if [[ -f $binding ]]; then
    current_label=$(jq -er '.full_name | strings' "$binding")
fi

# ===============================
# 🎮 4. 选择操作模式
# ===============================
printf '\n'
log "$CYAN" "对项目 [$project] ($current_label) 执行什么操作？"
printf '%s\n' '  [1] 🔄 同步到 Gitee' '  [2] 🗑️ 删除编译缓存与本地同步数据'
read -r -p "请输入选项 (1/2): " action || die "未读取到操作选项"
case "$action" in
    1|2) ;;
    *) die "无效的操作选项" ;;
esac

if [[ $action == 2 ]]; then
    log "$RED" "⚠️  将删除容器内的编译目录、宿主机上的本地 Git 历史和仓库映射。Gitee 远端仓库会保留。"
    read -r -p "确认清理 $project 吗？(y/n): " confirm || exit 1
    if [[ $confirm != y ]]; then
        log "$YELLOW" "已取消清理。"
        exit 0
    fi
fi

mkdir -p -- "$state"
exec 9>"$state/sync.lock"
flock -n 9 || die "该项目已有同步或清理任务正在运行"

if [[ $action == 2 ]]; then
    docker_container exec "$container" rm -rf -- "$source_dir"
    # 保留锁文件，避免并发任务在清理过程中拿到另一把锁。
    rm -rf -- "$repo_git"
    rm -f -- "$binding" "$state/gitee.json.tmp" "$state/last-success"
    log "$GREEN" "✅ 清理完成。"
    exit 0
fi

# ===============================
# 🚀 5. 同步逻辑
# ===============================
repo_name=''
if [[ ! -f $binding ]]; then
    read -r -p "请输入该项目的自定义标识（同时作为 Gitee 仓库名，例如 master_thesis）: " repo_name ||
        die "未读取到仓库名"
    [[ $repo_name =~ ^[a-z0-9][a-z0-9_-]*$ ]] ||
        die "仓库名请用小写字母、数字、短横线或下划线，并以字母或数字开头"
fi

# 从容器读取编译文件。Git 历史保存在宿主机的 repo.git。
log "$BLUE" "📂 正在读取编译目录 $source_dir ..."
snapshot=$(mktemp -d)
trap 'rm -rf -- "$snapshot"' EXIT
docker_container exec "$container" sh -c 'test -d "$1" && test ! -L "$1"' sh "$source_dir" ||
    die "编译目录不存在或不可读。请重新编译项目并运行 --list"
docker_container cp "$container:$source_dir/." "$snapshot/"
find "$snapshot" -mindepth 1 -iname .git -prune -exec rm -rf -- {} +
find "$snapshot" -maxdepth 1 -type f -name 'output.*' -delete
if [[ -z $(find "$snapshot" -type f -name '*.tex' -printf x -quit) ]]; then
    die "未找到 .tex 文件。请确认编译目录是否为目标项目"
fi

# 初始化本地 Git 历史，再检查新增、修改和删除。
if [[ ! -f $repo_git/HEAD ]]; then
    git init --quiet --bare --initial-branch=main "$repo_git"
fi
git_local() {
    git --git-dir="$repo_git" --work-tree="$snapshot" "$@"
}

git_local add -A -- .
diff_status=0
git_local diff --cached --quiet || diff_status=$?
case "$diff_status" in
    0) log "$YELLOW" "⚠️  没有内容更新，仍会检查远端并重试待推送提交。" ;;
    1) git_local -c user.name="Overleaf Sync" -c user.email="overleaf-sync@localhost" commit -m "$message" ;;
    *) die "Git 暂存区检查失败" ;;
esac
commit=$(git_local rev-parse --verify refs/heads/main) || die "没有可推送的文件"

if [[ -z ${GITEE_TOKEN:-} ]]; then
    read -r -s -p "输入 Gitee 私人令牌（输入不回显） " GITEE_TOKEN </dev/tty || die "请在终端输入令牌，或提供 GITEE_TOKEN"
    printf '\n' >&2
fi
[[ $GITEE_TOKEN =~ ^[A-Za-z0-9_.-]+$ ]] || die "令牌为空或格式无效"
# 通过标准输入传递认证头，避免令牌出现在 curl 命令行。
gitee_api() {
    printf 'Authorization: Bearer %s\n' "$GITEE_TOKEN" |
        curl -q --silent --show-error --fail --connect-timeout 15 --max-time 60 \
            --header @- --header 'Accept: application/json' "$@"
}

# 首次建空的私有仓库。先保存映射，推送失败时可以复用仓库重试。
if [[ ! -f $binding ]]; then
    log "$BLUE" "🛠️  正在创建 Gitee 私有仓库 $repo_name ..."
    payload=$(jq -cn --arg name "$repo_name" '{name:$name,path:$name,private:true,auto_init:false}')
    response=$(gitee_api --header 'Content-Type: application/json' --data "$payload" \
        'https://gitee.com/api/v5/user/repos') ||
        die "Gitee 建仓失败。请检查令牌的 projects 权限、仓库名及 Gitee 页面是否已有同名仓库"
else
    response=$(cat -- "$binding")
fi
full_name=$(jq -er '.full_name | strings' <<<"$response")
repo_id=$(jq -er '.id | numbers' <<<"$response")
[[ $full_name =~ ^[a-zA-Z0-9_-]+/[a-zA-Z0-9_.-]+$ ]] || die "Gitee 返回的仓库路径无效"
if [[ -n $repo_name && ${full_name#*/} != "$repo_name" ]]; then
    die "Gitee 仓库路径为 $full_name，与指定的仓库名不一致"
fi

if [[ ! -f $binding ]]; then
    jq -e '.private == true' <<<"$response" >/dev/null || die "建仓响应未确认仓库是私有的"
    jq -c '{id,full_name}' <<<"$response" > "$state/gitee.json.tmp"
    mv -f -- "$state/gitee.json.tmp" "$binding"
fi
# 推送前检查远端身份和私有状态。推送验证通过后更新菜单时间。
remote_info=$(gitee_api "https://gitee.com/api/v5/repos/$full_name") ||
    die "无法读取 Gitee 仓库 $full_name。请检查令牌与仓库是否仍可访问"
jq -e --argjson id "$repo_id" --arg path "$full_name" \
    '.id == $id and .full_name == $path and .private == true' <<<"$remote_info" >/dev/null ||
    die "远端仓库身份或私有状态校验失败"

remote="git@gitee.com:$full_name.git"
log "$BLUE" "🚀 正在同步至 $remote ..."
git_local push "$remote" refs/heads/main:refs/heads/main
remote_main=$(git_local ls-remote --exit-code "$remote" refs/heads/main)
[[ $remote_main == "$commit"$'\t'refs/heads/main ]] || die "远端 main 与本地提交不一致，请检查是否有其他推送"
printf '%s\n' "$(date -Iseconds)" > "$state/last-success"
log "$GREEN" "✅ 同步成功！https://gitee.com/$full_name  main $commit"
```
