**MaxiNet：与你的需求最直接对应**

它的结构是：Frontend 管理全局拓扑，各 Worker 运行一个 Mininet 实例，负责其中一部分节点；跨 Worker 的链路通过 GRE 隧道连接。Frontend 提供统一 API，记录节点所在的物理主机，因此使用者可以从一个入口操作整个实验网络。[maxinet.github.io](https://maxinet.github.io/?utm_source=chatgpt.com)

它能省去拓扑分配、远程操作和跨主机连接的基础工作。不过，官方安装文档仍列出 Debian 8、Ubuntu 14.04 和 Mininet 2.2.1rc1。**我建议把它作为首个验证对象，但不能据此认定它能直接兼容当前发行版和 Python 环境。**这次核查也没有足够证据断言其完全停止维护。[GitHub](https://github.com/MaxiNet/MaxiNet/blob/master/INSTALL.txt?utm_source=chatgpt.com)

**CORE + EMANE：如果信道建模是主要需求，值得优先评估**

CORE 可以把同一拓扑中的节点分配到多台服务器，并自动为跨服务器链路建立 GRE 隧道。一个明确限制是：CORE 自带的基础无线距离模型不能跨服务器工作，分布式无线网络需要使用 EMANE。[CORE Documentation](https://coreemu.github.io/core/distributed.html?utm_source=chatgpt.com)

EMANE 提供可插拔的 MAC/PHY 模型，以及位置、路径损耗等事件机制。它更适合研究无线介质对真实协议和应用流量的影响。但它并不自动提供完整的卫星信道：轨道、可见性、传播时延、多普勒等仍需根据所选模型配置或扩展。后一判断是根据其模型接口和事件机制做出的工程推断。[CORE Documentation](https://coreemu.github.io/core/emane.html?utm_source=chatgpt.com)

**Containernet、Mininet-WiFi：有用，但解决的是不同问题**

- **Containernet** 将 Docker 容器作为 Mininet 主机，适合运行微服务、VNF、MEC 应用。它的核心定位是容器主机支持，不能仅因支持 Docker 就把它视为完整的多主机编排工具。[GitHub](https://github.com/containernet/containernet?utm_source=chatgpt.com)
- **Mininet-WiFi** 提供无线节点、移动模型、传播模型和 wmediumd 集成，适合 Wi-Fi、车联网等实验；这些能力本身不能证明它已经提供成熟的跨物理主机无线部署。[mininet-wifi.github.io](https://mininet-wifi.github.io/?utm_source=chatgpt.com)
- **containerlab** 本体的官方文档仍说明不能直接自动部署跨多个容器主机的拓扑；分布式路线主要看 Clabernetes，而后者仍标为 Beta。[containerlab](https://containerlab.dev/manual/multi-node/?utm_source=chatgpt.com)

对你要构建的环境，我建议按下面的条件选择。这是工程选型建议，尚未经过你实际硬件环境的部署验证：

| 主要目标 | 建议路线 |
|---|---|
| 尽快跑通分布式 Mininet、复用现有 SDN 代码 | **先验证 MaxiNet** |
| 长期开发平台，频繁修改拓扑、链路和应用 | **Mininet / Containernet + OVS 隧道 + 自建统一编排** |
| 研究无线干扰、MAC 竞争、路径损耗对网络的影响 | **优先评估 CORE + EMANE** |
| 主要测试容器化网络系统、网络设备软件 | **评估 containerlab + Clabernetes** |

如果采用第二条路线，自建部分可以限定在四项：**各主机实例的启动与清理、全局节点与端口映射、跨主机链路管理、统一实验事件调度**。OVS 已有跨主机隧道连接方案；Mininet 的 `TCIntf` 支持带宽、时延、抖动、丢包和队列配置，并有运行时修改链路参数的官方示例。[Open vSwitch 4.0.90 documentation](https://docs.openvswitch.org/en/latest/howto/tunneling/?utm_source=chatgpt.com)

这里最影响选型的是信道精度：如果只需要让真实流量符合随时间变化的**带宽、时延、丢包和连通性**，Mininet 加动态链路配置就能作为基础；如果需要模拟**共享无线介质、干扰和 MAC/PHY 行为**，应进一步评估 EMANE。分布式执行和信道建模是两项独立能力，不能靠一个跨主机框架自动同时获得。
