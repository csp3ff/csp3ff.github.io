如果目标是**多台机器运行独立 Mininet、接入 SDN 控制器，并能替换空天地或 UAV–车网信道模型**，我会把项目分成三层：

1. **模型层**：根据位置、环境和业务负载计算信道状态。
2. **编排层**：统一推进仿真时间，决定链路何时建立、断开或更新。
3. **执行层**：在各机器上操作 Mininet、跨机隧道和 Linux `tc`。

关键边界是：模型只输出“链路应该是什么状态”，不直接调用 Mininet。这样以后更换信道公式，不必改动分布式部署代码。

## 核心接口应当先定下来

模型输出统一的数据结构，例如：

```python
@dataclass(frozen=True)
class ChannelState:
    link_id: str
    direction: str          # "a_to_b" 或 "b_to_a"
    available: bool
    bandwidth_mbps: float
    delay_ms: float
    jitter_ms: float
    loss_percent: float
    queue_packets: int | None = None
```

```python
class ChannelModel(Protocol):
    def evaluate(
        self,
        time_s: float,
        transmitter: NodeState,
        receiver: NodeState,
        environment: EnvironmentState,
    ) -> ChannelState:
        ...
```

数据流是：

```text
节点轨迹 + 环境参数
        ↓
覆盖/可见性判断
        ↓
路径损耗、干扰、SINR、PER 等模型
        ↓
ChannelState
        ↓
coordinator 分发
        ↓
对应 worker 在链路接口上设置 tc / 更新连接状态
```

`ChannelState` 是整个项目最重要的接口。信道模型负责计算，`tc.py` 负责执行。Mininet 的 `TCIntf.config()` 已提供带宽、时延、抖动、丢包等配置入口；Linux `netem` 还能处理更复杂的丢包和时延行为。([mininet.org][1])

## 多机部分要明确“逻辑链路”和“实际接口”

例如逻辑链路 `sat-03 ↔ uav-07` 横跨机器 A、B，系统需要记录：

| 对象    | 示例               | 用途                |
| ----- | ---------------- | ----------------- |
| 逻辑链路  | `sat-03__uav-07` | 供模型、拓扑和日志引用       |
| A 端接口 | `veth-s03-u07`   | 控制 A→B 的出站流量      |
| B 端接口 | `veth-u07-s03`   | 控制 B→A 的出站流量      |
| 跨机承载  | 隧道或其他连接          | 把两个 Mininet 实例连起来 |

这就是 `link_registry.py` 的职责。不要让信道模型依赖 `s1-eth3` 之类临时接口名。双向信道也要分别建模：A→B 与 B→A 的干扰、速率和丢包可能不同。

另外，跨机物理网络本身已有时延和带宽限制。实验记录中应保存**目标链路参数、施加到接口的参数、实际测量结果**三者，避免把真实网络开销误当成模型效果。

## 每个仿真时间步做什么

假设以 1 秒为一个更新周期：

1. `coordinator` 发布时间 \(t\) 和随机种子。
2. `mobility` 更新卫星、UAV、车辆的位置。
3. `connectivity` 判断哪些节点仍可通信。
4. `models` 为每条有向链路计算 `ChannelState`。
5. `coordinator` 计算与上一轮的差异，只发送变化。
6. 各 `worker` 更新本机接口，并回报执行结果。
7. `recorder` 写入模型输出、执行结果和测量值。

断链需要单独定义语义：是**接口/端口消失、链路 down**，还是**链路仍存在但丢包率为 100%**。这两种情况给 SDN 控制器的观测结果不同，不能混用。

## 场景配置示例

```yaml
name: uav_vehicle_demo
duration_s: 600
step_s: 1
seed: 2026

controller:
  host: 10.0.0.10
  port: 6653

channel:
  model: uav_vehicle
  carrier_hz: 2.4e9
  spectrum_bandwidth_hz: 20e6
  tx_power_dbm: 20
  noise_figure_db: 7
  max_range_m: 2000

nodes:
  - id: uav-01
    kind: uav
    worker: machine-a
    trajectory: trajectories/uav_01.csv

  - id: vehicle-01
    kind: vehicle
    worker: machine-b
    trajectory: trajectories/vehicle_01.csv
```

论文实验中，`seed`、轨迹、配置文件、模型版本和每轮 `ChannelState` 都应保留，才能重放同一次实验。

**实施顺序**建议是：先用单机两节点验证“动态改变参数确实改变 ping/iperf3 结果”；再加入 OVS 与控制器；最后加入跨机隧道和统一时钟。模型层可逐步从距离经验映射，替换为路径损耗、干扰和 PER 模型。ns-3 将传播损耗、传播时延等作为独立模型处理，这种拆分方式也适合作为你的 Python 模型层设计参考。([Model Library][2])
