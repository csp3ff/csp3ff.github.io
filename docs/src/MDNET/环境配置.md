# Ubuntu 18.04 安装 Mininet、Open vSwitch、Ryu 与 Python 3.10

本文整理 MDNET 项目的 Mininet 与 Ryu 中央控制器环境安装方案，目标系统是 Ubuntu 18.04。内容包括版本选择、系统依赖、Python 源码安装、Mininet、Ryu 和项目虚拟环境，以及下载慢时的镜像与代理配置。

**状态：安装方案，尚未在目标机执行或验证。** 当前项目约定是不运行部署逻辑，也不运行代码测试。文中的安装命令供准备目标机时使用；网络启动与连通性测试留待项目允许后进行。

## 1. 版本组合与适用范围

| 组件 | 约定版本 | 安装位置与原因 |
| --- | --- | --- |
| Ubuntu | 18.04 LTS，`bionic` | 目标机器现有系统 |
| Python | 3.10.22 | 源码安装到 `/opt/python-3.10.22`，不替换系统 Python |
| Mininet | 2.3.0 | 从官方 Git 标签安装到项目虚拟环境；2.3.0 支持 Python 3 |
| Open vSwitch（OVS） | Ubuntu 18.04 的 2.9.8 系列 | 通过 `openvswitch-switch` 系统包安装，与发行版内核配套 |
| Ryu | 4.34 | 项目的 `controller` 可选依赖；与 Mininet 分进程启动 |
| Ryu 构建依赖 | setuptools 67.8.0、PBR 5.11.1 | 仅在构建 Ryu 时固定；MDNET 自身仍用隔离构建环境 |
| MDNET | 当前项目源码 | 与 Mininet、Ryu 安装在同一个 Python 3.10 虚拟环境 |

Ubuntu 18.04 的 `apt install mininet` 提供 Mininet 2.2.2，不能把它当成本方案需要的 Python 3 版本。Mininet 官方说明 2.3.0 起支持 Python 3，且 2.3.0 发布时提供 Ubuntu 18.04 虚拟机镜像。OVS 的 Ubuntu 18.04 包属于 2.9.8 系列；具体 Debian 包修订号以目标机软件源为准。参见 [Mininet 下载与安装说明](https://mininet.org/download/)、[Mininet 2.3.0 发布页](https://github.com/mininet/mininet/releases/tag/2.3.0)和 [Ubuntu OVS 安全公告](https://ubuntu.com/security/notices/USN-6068-1)。

Python 3.10.22 是 3.10 系列的最终版本，3.10 已于 2026 年 10 月 1 日结束维护。Ubuntu 18.04 也已结束常规支持，后续使用需考虑 Ubuntu Pro/ESM 或系统升级。这里仍按现有目标机和 Python 3.10 要求给出可复现的安装步骤。参见 [Python 3.10.22 发布说明](https://www.python.org/downloads/release/python-31022/)和 [Ubuntu 18.04 支持说明](https://ubuntu.com/18-04)。

本项目默认的 `up` 入口使用 Mininet 的 `Host`、`OVSBridge` 和 `ovs-vsctl`；指定远程控制器后使用 OpenFlow 1.3 交换机。已有独立的 Ryu 中央控制器入口，但受控模式尚未运行验证；跨物理机器链路和节点容器化尚未实现。Mininet 创建网络需要 root 权限，控制器进程不需要。

## 2. 安装系统依赖与 OVS

以下命令在 **Ubuntu 18.04 目标机** 执行。先保证目标机的 Ubuntu 软件源可用，再安装构建 Python 和运行基础 Mininet 所需的软件包：

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential ca-certificates git wget \
  libssl-dev zlib1g-dev libbz2-dev libreadline-dev \
  libsqlite3-dev libffi-dev liblzma-dev libncursesw5-dev \
  libgdbm-dev uuid-dev \
  openvswitch-switch iproute2 iputils-ping net-tools \
  ethtool socat psmisc

sudo systemctl enable --now openvswitch-switch
```

Open vSwitch 官方文档建议 Ubuntu 使用 `openvswitch-switch` 和 `openvswitch-common` 包；后者由包依赖安装。无需单独编译 OVS 内核模块。参见 [OVS 发行版包说明](https://docs.openvswitch.org/en/latest/intro/install/distributions/)。若目标机已经安装 OVS，先查看 `apt-cache policy openvswitch-switch`，确认软件源与版本，再决定是否更新。

## 3. 安装 Python 3.10.22

Python 3.10 要求 OpenSSL 1.1.1 或更新版本，因此要先从可用的 Ubuntu 18.04 软件源安装更新后的 `libssl-dev`。源码安装使用 `altinstall`，以免覆盖系统的 `/usr/bin/python3`。参见 [Python 3.10 变更说明](https://docs.python.org/3.10/whatsnew/3.10.html)和 [Python Unix 安装说明](https://docs.python.org/3.10/using/unix.html)。

### 3.1 下载源码

网络直连 Python 官网较慢时，可以使用已收录 `Python-3.10.22.tgz` 的[阿里云 Python 源码镜像](https://mirrors.aliyun.com/python-release/source/)：

```bash
mkdir -p "$HOME/src"
cd "$HOME/src"
wget -c https://mirrors.aliyun.com/python-release/source/Python-3.10.22.tgz
```

若目标机已有可访问的 HTTP 代理，也可以从官方地址下载。将示例中的代理地址、端口改为目标机实际可访问的值：

```bash
https_proxy=http://127.0.0.1:7890 \
http_proxy=http://127.0.0.1:7890 \
wget -c https://www.python.org/ftp/python/3.10.22/Python-3.10.22.tgz
```

这里的 `127.0.0.1` 指 **Ubuntu 目标机**。若代理运行在另一台电脑上，应使用目标机可连接的代理地址，或另行建立 SSH 端口转发。`wget` 支持 `http_proxy`、`https_proxy` 环境变量；`-c` 用于续传。参见 [GNU Wget 代理说明](https://www.gnu.org/software/wget/manual/html_node/Proxies.html)。

无论从哪里下载，解压前都要用[官方发布页](https://www.python.org/downloads/release/python-31022/)的 SHA-256 校验：

```bash
printf '%s  %s\n' \
  '9448b34d16f8e3db0964ac3ed9fb283197747543c2c021f283ffd2c8b7287357' \
  'Python-3.10.22.tgz' | sha256sum -c -
```

应看到 `Python-3.10.22.tgz: OK`。若校验失败，删除损坏的下载文件后重新下载。

### 3.2 编译安装

```bash
cd "$HOME/src"
tar -xzf Python-3.10.22.tgz
cd Python-3.10.22
./configure --prefix=/opt/python-3.10.22 --with-ensurepip=install
make -j2
sudo make altinstall
```

安装后的解释器路径是 `/opt/python-3.10.22/bin/python3.10`。`make -j2` 将并行编译限制为两个任务；目标机资源充足时可以调整。

## 4. 安装 Mininet 2.3.0 与 MDNET

以下假定已将 **同一份 MDNET 源码** 复制到目标机的 `~/MDNET`；若位置不同，修改 `APP_DIR`。Mininet 仍从官方 GitHub 获取，并固定 `2.3.0` 标签：

```bash
git clone --depth 1 --branch 2.3.0 \
  https://github.com/mininet/mininet.git \
  "$HOME/src/mininet-2.3.0"

APP_DIR="$HOME/MDNET"
/opt/python-3.10.22/bin/python3.10 -m venv "$APP_DIR/.venv"
```

这里的 Mininet 从源码安装进虚拟环境，因此 **不需要** README 中针对系统包 Mininet 使用的 `--system-site-packages`。项目的 `pyproject.toml` 要求 Python ≥3.10。

### 4.1 仅为当前终端的 pip 换源

Git 下载和 pip 下载是两件事。以下配置只影响当前终端的 pip 命令，包括安装本地源码时下载构建依赖；不会修改 Git 地址，也不会修改系统 Python。使用[清华 PyPI 镜像](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/)：

```bash
export PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple

"$APP_DIR/.venv/bin/python" -m pip install --upgrade pip setuptools wheel
"$APP_DIR/.venv/bin/python" -m pip install pexpect "$HOME/src/mininet-2.3.0"
"$APP_DIR/.venv/bin/python" -m pip install -e "$APP_DIR"
```

本地的 Mininet 和 MDNET 源码不会从 PyPI 下载；镜像主要用于 `pip`、`setuptools`、`wheel`、`pexpect` 以及构建依赖。若换了终端，需重新执行 `export PIP_INDEX_URL=...`。不要使用 `sudo pip` 安装到 Ubuntu 18.04 的系统 Python。

### 4.2 安装 `mnexec`

Mininet 的 Python 包之外，还需要 `mnexec` 可执行程序来创建网络命名空间中的主机进程。使用同一个虚拟环境编译后安装到系统路径：

```bash
make -C "$HOME/src/mininet-2.3.0" \
  PYTHON="$APP_DIR/.venv/bin/python" mnexec

sudo install -m 0755 \
  "$HOME/src/mininet-2.3.0/mnexec" \
  /usr/local/bin/mnexec
```

该编译目标来自 [Mininet 2.3.0 Makefile](https://github.com/mininet/mininet/blob/2.3.0/Makefile)。

### 4.3 安装 Ryu 4.34 中央控制器依赖

项目在 `pyproject.toml` 中将 `ryu==4.34` 声明为 `controller` 可选依赖。Ryu 4.34 的构建脚本使用了 setuptools 68 已移除的 `easy_install.get_script_args`；直接安装项目的控制器依赖可能在 Ryu 的构建阶段失败。关闭构建隔离时，还需预先安装 Ryu 的 `setup_requires=['pbr']`，否则会报 `Unknown distribution option: 'pbr'` 和 `Multiple top-level packages discovered`。参见 [Ryu 4.34 的 setup.py](https://github.com/faucetsdn/ryu/blob/v4.34/setup.py)、[setuptools 68 变更记录](https://setuptools.pypa.io/en/latest/history.html#v68-0-0)和 [pip 构建隔离说明](https://pip.pypa.io/en/stable/reference/build-system/#disabling-build-isolation)。

继续在目标机的项目目录执行；如果换了终端，先重新设置前文的 `PIP_INDEX_URL`：

```bash
APP_DIR="$HOME/MDNET"
cd "$APP_DIR"
"$APP_DIR/.venv/bin/python" -m pip install 'setuptools==67.8.0' 'pbr==5.11.1' wheel
"$APP_DIR/.venv/bin/python" -m pip install --no-build-isolation --no-deps 'ryu==4.34'
"$APP_DIR/.venv/bin/python" -m pip install -e '.[controller]'
```

`--no-build-isolation` 只用于构建 Ryu，使其使用虚拟环境内的旧版 setuptools 和 PBR。`--no-deps` 只用于这一步；最后一条命令正常安装 Ryu 的其他依赖。MDNET 自身仍按 `pyproject.toml` 在隔离环境中使用 setuptools 68 或更新版本。不要使用 `sudo pip`。

控制器与 Mininet 分别启动。以下命令仅供后续允许运行时使用，本文未执行：

```bash
APP_DIR="$HOME/MDNET"
cd "$APP_DIR"
./.venv/bin/md-controller configs/two_workers.json --listen-host 127.0.0.1 --listen-port 6653
```

在另一终端、同一台机器上，用相同场景连接控制器：

```bash
APP_DIR="$HOME/MDNET"
cd "$APP_DIR"
sudo ./start.sh --controller-host 127.0.0.1 --controller-port 6653
```

该示例的受控模式需在单机启动完整拓扑；当前 `--worker` 分区模式没有跨物理机器链路。Ryu 4.34 已[停止维护](https://github.com/faucetsdn/ryu)。它导入新版 Eventlet 时可能因缺少 `ALREADY_HANDLED` 而退出；MDNET 的 `md-controller` 入口已按 [Ryu 后续源码](https://github.com/faucetsdn/ryu/blob/master/ryu/app/wsgi.py)对缺失符号提供兼容值，目标机须使用包含这项修正的 MDNET 源码。Eventlet 的弃用提示只是警告，不表示启动成功。上述构建步骤尚未在本文目标机验证，安装成功也不等于控制器运行验证通过。

## 5. 版本与配置核对

以下命令仅查看安装信息，不创建网络、启动项目或运行连通性测试：

```bash
/opt/python-3.10.22/bin/python3.10 --version
"$APP_DIR/.venv/bin/python" --version
"$APP_DIR/.venv/bin/python" -m pip show mininet md-mininet ryu pbr setuptools
apt-cache policy openvswitch-switch
ovs-vsctl --version
systemctl is-active openvswitch-switch
command -v mnexec
```

预期 Python 为 `3.10.22`，Mininet 为 `2.3.0`，Ryu 为 `4.34`，PBR 为 `5.11.1`，虚拟环境内的 setuptools 为 `67.8.0`，OVS 为 Ubuntu 18.04 的 `2.9.8` 系列，OVS 服务状态为 `active`，`mnexec` 位于 `/usr/local/bin/mnexec`。这些是安装核对项，**不表示拓扑或控制器已经验证**。

## 6. sudo、Worker 一致性与常见问题

项目的 `up` 命令需要 root 权限。以后允许启动网络时，应使用项目虚拟环境里的 `md-mininet` 入口，并从项目根目录运行；不要让 `sudo` 默认选择系统 Python 3.6。普通用户安装的 `.venv` 和项目源码会被 root 执行，因此应只使用可信的项目文件，并限制无关用户对它们的写权限。

每台 Worker 应使用相同的 Mininet 标签、Python 3.10.22、OVS 2.9.8 系列、MDNET 源码和场景配置；可记录 `apt-cache policy` 的包修订号以及场景文件的 SHA-256，以便排查环境差异。当前 `--worker a` 与 `--worker b` 各自只启动本地拓扑，**不会自动建立跨物理机器链路**。

| 现象 | 先检查什么 |
| --- | --- |
| `No module named mininet` | 是否使用了 `"$APP_DIR/.venv/bin/python"`；Mininet 是否安装到同一虚拟环境 |
| `mnexec` 找不到 | `/usr/local/bin/mnexec` 是否存在；root 执行时的 `PATH` 是否包含 `/usr/local/bin` |
| `ovs-vsctl` 连接失败 | `openvswitch-switch` 是否安装、服务是否为 `active` |
| pip 下载慢 | 当前终端是否设置了 `PIP_INDEX_URL`；镜像地址末尾是否有 `/simple` |
| GitHub 克隆慢 | pip 换源不会加速 Git；需另行配置 Git 的代理或在可访问 GitHub 的机器上取得相同标签的源码 |
| Python 构建缺少 SSL 支持 | 检查 `libssl-dev` 版本与 Python 3.10 所需的 OpenSSL 1.1.1 条件 |
| Ryu 构建报 `get_script_args` 缺失 | 按 4.3 节先固定 setuptools 67.8.0，再仅对 Ryu 使用 `--no-build-isolation` |
| Ryu 构建报 `Unknown distribution option: 'pbr'` | 按 4.3 节预先安装 PBR 5.11.1，然后重新构建 Ryu |
