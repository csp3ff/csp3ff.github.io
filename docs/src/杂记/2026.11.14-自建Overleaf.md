# 自建 Overleaf 与中文 Beamer 排错记录

我在 X99 Linux 主机上用 Overleaf Toolkit 部署 Community Edition，通过已有的 frp SSH 通道从 Windows 电脑访问。编译中文 Beamer 项目时，遇到了 Docker 权限、TeX Live 缺包、上传路径和中英文字体等问题。下文的容器命令均在 X99 的 `overleaf-toolkit` 根目录执行，另有说明的命令除外。

## 问题 1：Docker 套接字权限阻止 Overleaf 启动

`bin/init` 已生成 `config/`，但执行 `bin/up` 时出现 `permission denied ... /var/run/docker.sock`。错误中虽然提到了 `mongo:8.0`，Docker 客户端当时连守护进程都没能访问。

## 解决方法 1

1. 给部署账户加入 `docker` 组，并让新 shell 立即使用这项权限。
2. 用 `docker ps` 验证。成功后用 `bin/up -d` 启动。

```bash
sudo usermod -aG docker "$USER"
newgrp docker
docker ps && bin/up -d
```

`docker` 组具有 root 级权限，适用于可信账户。[Docker 官方文档](https://docs.docker.com/engine/install/linux-postinstall/)

## 问题 2：Windows 浏览器需要访问 X99 的回环地址

Overleaf 监听 X99 上的 `127.0.0.1:80`。本地电脑已经能通过 frp SSH 登录 X99，需要把远端的网页端口转发到本地。

## 解决方法 2

在 Windows PowerShell 中沿用现有 SSH 登录配置。下面假设 SSH 别名是 `x99`。

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8080:127.0.0.1:80 x99
```

如果平时用 `ssh -p 6000 csp@frps.example.com`，就把命令最后的 `x99` 换成 `-p 6000 csp@frps.example.com`，并填入实际地址和端口。前一个 `127.0.0.1:8080` 是 Windows 上的监听地址，后一个 `127.0.0.1:80` 是 X99 上的 Overleaf 地址。保持 SSH 窗口打开，在浏览器访问 [http://127.0.0.1:8080](http://127.0.0.1:8080)。[OpenSSH 手册](https://man.openbsd.org/ssh.1)

## 问题 3：Overleaf 容器缺少 Beamer 和其他 LaTeX 宏包

项目先报 `beamer.cls not found`，后续又遇到了 `booktabs.sty` 和 `cancel.sty` 缺失。`No PDF` 和 `Emergency stop` 是编译中止后的提示。诊断时应从原始日志开头找第一条 `File ... not found`，行号可能指向 TeX 停下来等待输入的位置。

## 解决方法 3

1. 查容器内的 TeX Live 年份。这里查到的是 `/usr/local/texlive/2026`。
2. 用同年份的仓库补包。下面合并了这份 Beamer 项目直接加载的扩展包和本次报错中出现的包。`calligra.sty` 对应 `fundus-calligra`。
3. 若 `tlmgr` 提示必须先更新自身，先执行下面的 `update --self`。安装后检查关键文件的路径，并在网页里选择 **XeLaTeX**，执行 **Recompile from scratch**。

```bash
bin/docker-compose exec -T sharelatex kpsewhich -var-value=TEXMFROOT

bin/docker-compose exec -T -u root sharelatex sh -ec '
  repo=https://mirrors.tuna.tsinghua.edu.cn/CTAN/systems/texlive/tlnet
  tlmgr --repository "$repo" update --self
  tlmgr --repository "$repo" install \
    beamer ctex xecjk fandol booktabs fundus-calligra \
    pstricks listings stackengine fontawesome5 ragged2e cancel
  tlmgr path add
  kpsewhich beamer.cls
  kpsewhich booktabs.sty
  kpsewhich cancel.sty
  xelatex --version
'
```

这组命令适用于镜像仓库与容器 TeX Live 年份一致的情况。普通重启会保留容器内补装的包，Compose 重建容器会重新从镜像创建。若需要保留补包结果，可在编译验证通过后按官方文档提交为本地镜像，并更新 `config/version`。  
[Overleaf 官方补包与持久化步骤](https://docs.overleaf.com/on-premises/installation/upgrading-tex-live) · [清华 CTAN 镜像](https://mirrors.tuna.tsinghua.edu.cn/help/CTAN/) · [fundus-calligra](https://ctan.org/pkg/fundus-calligra)

## 问题 4：X99 宿主机已有 TeX Live，网页编译仍然缺包

X99 宿主机用的是 Debian 打包的 TeX Live 2022/dev，`TEXMFROOT` 为 `/usr/share/texlive`。网页编译用的是容器内的 TeX Live 2026。在 `config/` 目录直接运行 `bin/docker-compose` 还会报脚本找不到，因为路径相对于当前目录。

## 解决方法 4

1. 回到 `overleaf-toolkit` 根目录执行下面的命令。留在 `config/` 时，脚本路径写成 `../bin/docker-compose`。
2. 通过 `kpsewhich` 分别检查两边。它打印路径时，表示对应环境找到了文件。
3. 网页编译继续使用 2026，并在容器内补包。Debian 将可执行文件、宏包、配置和生成的格式文件分开放置，单独挂载 `/usr/share/texlive` 无法迁移整套安装。需要复现旧版编译结果时，可以直接在安装了相关依赖的宿主机上用 2022 编译。

```bash
kpsewhich -var-value=TEXMFROOT
kpsewhich beamer.cls
bin/docker-compose exec -T sharelatex kpsewhich -var-value=TEXMFROOT
bin/docker-compose exec -T sharelatex kpsewhich beamer.cls
```

本次还遇到 `SIBLING_CONTAINERS_ENABLED=true` 警告。Community Edition 会回退到 `sharelatex` 容器内编译。可在 `config/overleaf.rc` 中设为 `false`，再用 `bin/up -d` 应用设置。  
[Debian 的 TeX Live 布局](https://wiki.debian.org/TeXLive) · [Toolkit 设置](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/toolkit-settings)


## 问题 5：使用 `\textit` 时只有英文倾斜

正文开头的 `\kaishu` 会让中文使用 `zhkai` 字族。配置默认无衬线字族的 `\setCJKsansfont` 无法改变该楷体字族的斜体效果。

## 解决方法 5

在 `\usepackage{Southeast}` 后、`\begin{document}` 前定义楷体的粗体和斜体。下面通过 XeLaTeX 合成字重和斜度，适用于前面选定的 Fandol 字库。正文保留 `\kaishu`，并把需要倾斜的中英文一并放入 `\textit{...}`。

```latex
\setCJKfamilyfont{zhkai}[
  BoldFont           = FandolKai-Regular.otf,
  BoldFeatures       = {FakeBold=2},
  ItalicFont         = FandolKai-Regular.otf,
  ItalicFeatures     = {FakeSlant=0.2},
  BoldItalicFont     = FandolKai-Regular.otf,
  BoldItalicFeatures = {FakeBold=2, FakeSlant=0.2}
]{FandolKai-Regular.otf}

% 正文示例
% \textit{研究 SAGIN 下网络资源分配的架构与算法}
```

[CTeX 字体配置](https://texdoc.org/serve/ctex.pdf/0) · [fontspec 手册](https://ctan.org/pkg/fontspec)

## 问题 6：需要给 Beamer 的内层列表加一个整体边框

一条外层项目符号介绍两项课题，下面的两条编号说明需要共享同一个文本框。

## 解决方法 6

用 `\fbox` 画边框，用 `minipage` 装入内层列表。宽度从当前的 `\linewidth` 扣除两边的边距和线宽。用 `\par` 让说明在各自标题下另起一行。

```latex
\begin{itemize}
  \item 围绕导师国自然基金开展两项硕士研究课题

  \par\smallskip\noindent
  \fbox{%
    \begin{minipage}{\dimexpr\linewidth-2\fboxsep-2\fboxrule\relax}
      \begin{itemize}
        \item[1.] 空天地一体化弹性网络关键技术（国家自然科学基金）
          \par\textit{研究 SAGIN 下网络资源分配的架构、算法}
        \item[2.] 多域网络环境下的网络资源分配（拓展课题 1）
          \par\textit{将 SAGIN 拓展到一般多域网络，探究更加通用的解决范式}
      \end{itemize}
    \end{minipage}%
  }
\end{itemize}
```
